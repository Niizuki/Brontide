# Agent feedback — 2026-W33

## Fresh independent review found contract contradictions behind a green gate

Date: 2026-08-11
Trigger: a rule caught something you can name

PB8's three fresh-context reviews examined a Portable Binding contract for which the existing
neutral gate passed all 83 vectors. The neutral reviewer nevertheless found that the Composition
handoff schema contradicted the already resolved provider-identity rule, withdrawal promised a legal
late Outcome without defining such a transition, nine vectors had no truthful representation for an
unobservable provider effect count, and no capability had a property quantified over all of its
vectors. The reviews also found stale implementation-target and Channel-execution claims that the
mechanical gate did not check.

When a milestone's evidence is derived from shared declarations, a green artifact/vector gate cannot
substitute for the required fresh-context review: all consumers can agree with the same incorrect or
silent declaration. Preserve the first negative attestations, pin each finding with a gate or native
regression before correcting it, and require a fresh re-review of the corrected commit.

## Programme closure must sweep routing claims

Date: 2026-08-11
Trigger: a rule caught something you can name

While recording Channel 0.2 as the next work, the documentation-cleanup rule required the changed
programme status to be propagated beyond the new plan. That sweep found the root README still naming
Portable Component Binding 0.1 as the next implementation goal and an Architecture 0.7 target, both
stack experiment inventories still saying PB8's independent reviews were outstanding, and the PB
plan and future-work index still calling PB8 partial after its review closure had merged.

When a governed programme closes or a successor becomes the next priority, search repository entry
points, both stack status inventories, and the owning plan for the old phase/status phrases. Updating
only the new or owning document leaves different consumers with different routing instructions even
when every link remains valid.

## The reviewer-does-not-repair rule and the handoff's own next step point different ways

Date: 2026-08-11
Trigger: two rules that pointed different ways

The Channel 0.2 design-review policy says "The reviewer writes only its requested attestation. It
does not repair the design it reviews." The same file's exact-next-work handoff says that if the
verdict is negative, the agent should "add failing verifier/model checks for each new finding,
correct the design in a later commit, and obtain another fresh review." An agent asked to finalize
the batch in one session satisfies one or the other, never both: writing the attestation and then
correcting makes it the author of the repair it found, and stopping after the attestation leaves the
design verifier red, because that verifier asserts the exact set of retained attestation filenames
and a fifth file trips it.

The separation the first rule protects is real, but it is a constraint on *actors*, not on sessions,
and nothing in the policy says which actor performs step 3. State that explicitly: either the
correction is the reviewer's own next task and the independence requirement applies only to the
following review, or the correction requires a different actor and the handoff should say so. Where
one session does both, record the overlap where the next reviewer will see it rather than leaving it
to be inferred from commit authorship.

## A status line that names its pending review is worth pinning in the gate

Date: 2026-08-11
Trigger: an approach that worked, is not in AGENTS.md, and would generalise

Four successive independent reviews of one document set were named "closure", "final closure",
"definitive closure", and "totality closure". Three artifacts were left with status blocks awaiting a
cycle that had already run - one of them two cycles behind - while their normative content had in
fact been corrected. Every structural gate passed throughout, because a gate that checks headings,
vocabulary, and inventory subsets cannot tell that a document is claiming to have survived a review
it never saw.

Two things fixed it and both generalise. Name review cycles by number or by one stable phrase rather
than by escalating adjective, because the adjective is what goes stale. And assert the phrase in the
gate: the design verifier now requires each artifact's status block to name the review it awaits and
rejects a block naming a superseded one, which makes "this document's status is current" something
the suite answers rather than something the author remembered.
