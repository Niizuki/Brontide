# Agent feedback — 2026-W36

## A negative prose guard's extent is part of the claimed scenario

Date: 2026-08-31
Trigger: a rule caught something that can be named

The rule that every comment claim under a named scenario is a test case exposed five verification
guards whose comments named a whole sentence, paragraph, or clause while their code read only 24 to
600 characters. Each guard executed and passed, so conditional coverage reported it as covered; a
probe that kept the forbidden text inside the named subject but moved it beyond the numeric bound
made the mismatch visible. The Channel 0.2 facts gate accepted positional field wording 1,125
characters after a rendered field list in the same paragraph, and four sibling probes reproduced the
same failure in abbreviated-publication, retained-review, duplicate-measure, and per-session-fact
checks.

When a comment says a negative prose guard covers a sentence, paragraph, or clause, the test should
place forbidden text at the far end of that semantic unit. Executing the guard once is insufficient:
truncation makes a positive assertion fail loudly and a negative assertion pass silently.
